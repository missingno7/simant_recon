# SimAnt (DOS) historical reconstruction

Byte-matching reconstruction of the DOS `SIMANT.EXE` (Maxis, Dec 1991): readable C and
genuine assembly that the period Microsoft toolchain compiles to exactly the original
bytes, fixups and relocations. This is not a port. The reconstruction will be frozen as an
oracle before any platform code is replaced (see "After the freeze").

Current totals are in [docs/progress.md](docs/progress.md) (generated by `validate.py`).

## What the original is

* MZ root image + **Pocket Soft RTLink/Plus** overlays (27 overlay sections in 4 areas,
  one resident data section, 136 vectors) — [docs/exe-format.md](docs/exe-format.md).
* **Microsoft C 6.00(A), large model, `/Os`** (+ per-module `/Oe`, `/Gs`, `_fastcall`),
  MSC 6.00-generation runtime, genuine MASM modules —
  [docs/toolchain-fingerprint.md](docs/toolchain-fingerprint.md).
* Large model ⇒ one code segment per source file: module boundaries are visible —
  [docs/tu-evidence.md](docs/tu-evidence.md).
* The Win16 reconstruction (`D:\Prog\simantw_recon`) is the cross-version semantic
  oracle — [docs/cross-version.md](docs/cross-version.md).

## Setup

Python 3.10+ with `capstone` (5.x). Original files stay in ignored `assets/`
(identities in `layout/oracle.lock.json`). Historical tools live in `C:\tools`
(catalog and provenance there) and are hash-pinned in `layout/toolchain.json`; they run
under MS-DOS Player (`C:\tools\nmlgcdos\msdos.exe`). Nothing in Git contains original or
tool binaries. In Git Bash set `MSYS_NO_PATHCONV=1` when passing `/AL`-style flags.

## Everyday workflow

```
python tools/context.py FUNCTION          # evidence packet (FUNCTION = name or UNIT:SEG:OFF)
python tools/context.py --list SUBSTR     # find functions
# write the module file draft in build/workers/NAME/ (one C file per original code segment)
python tools/search.py FUNCTION draft.c [more.c] [--flags /AL /Os /Oe] [--placement CONST=55B3:7E28]
python tools/promote.py draft.c --module root:0093 --claim NAME [--claim ...] [--extent START:END] --verify-only
python tools/promote.py draft.c --module root:0093 --claim NAME ...
python tools/validate.py                   # at acceptance/tooling boundaries
```

Other tools: `probe.py SPEC.json` (controlled compiler experiments, rules in
[docs/codegen-rules.md](docs/codegen-rules.md)), `xver.py build|show|strings|apply-names`
(correspondence), `libmatch.py` (runtime location), `inventory.py` (function discovery),
`oracle.py` (lock), `symbols.py` / `functions.py` (registry maintenance).

## State and proof

* `layout/oracle.lock.json` — immutable description of every original input (never an
  input to reconstruction).
* `layout/manifest.json` — the only ownership authority: modules, profiles, claims,
  private data placements, complete-TU extents. Written only by `promote.py`.
* `layout/functions.json`, `layout/symbols.json` — function table (recursive descent +
  reviewed rows) and names registry (each address grounded; renames keep evidence).
* `src/<unit>/m<SEG>.c|.asm` — canonical module sources.
* `evidence/` — promotions journal, codegen rule reproducers, cross-version database.
* `build/` — derived and scratch output; never authoritative.

Acceptance (strict, no masking): the candidate segment's extent has the target length;
every fixup binds symbolically (runtime publics, registered code/data names, own segment,
declared placements, RTLink vectors for cross-overlay calls); bound bytes equal the
original; the relocation set equals the oracle's; private `CONST`/`_DATA` placements
reproduce their bytes and data relocations; `_BSS` placements lie in DGROUP's BSS.
Data-only translation units (`data:FRAME`, `src/data/`) own far data placements and no claims;
they count as accepted data, never as recovered code (docs/tu-evidence.md).
Relocation *order* is recorded separately until the RTLink model is known.
Similarity scores are diagnostics only.

## Proof levels (kept distinct)

1. exact reconstructed contributions (today),
2. oracle-assisted hybrid image equality (future: `validate.py --image`),
3. independently reconstructed historical link (future: needs RTLink).

## After the freeze

When the DOS reconstruction reaches historical closure it will be tagged immutable. A
separate branch will then keep the simulation/game core and replace the DOS window
system with host-native windows (`game/`, `ui_model/`, `platform/{dos_legacy,native_windows}`),
using the Win16 build as the design reference. Historical sources are not changed to
ease that port.
