# Standalone DOS closure strategy

The highest-leverage step is now an independent real link plus targeted original
runtime observations. Compiling another individually exact function does not
resolve the remaining ownership, input-domain and runtime-selection questions.
The generated [status and dependency graph](status.md) is the current queue;
`src/program.json` owns its roots, edges and DOS membership. Graph coverage,
cycles and stale leaves are checked by `tools/repository.py`.

## What the sibling projects actually contribute

Stunts' `tools/data_extent_generator.py` combines a dominating guard, the same
scaled index, a complete write/reference set and independent object anchors.
It distinguishes an access bound from allocation authority. Its ring-buffer
and near-DGROUP recognizers do not directly fit SimAnt's far ES accesses and
enregistered indices: a trial over 1,730 SimAnt functions produced no witnesses.
The unused adaptation was retired, rather than installed as another empty proof
engine. Resource decoding here reuses the existing independently checked
database/LZSS decoder and adds menu/window/style topology checks.

Stunts' `tools/runtime_link_probe.py` and real LINK workflow make linking an
experimental instrument, separate from acceptance. Its `docs/unresolved.md`
allows opaque semantics when complete extents and behavior remain preserved;
that does not authorize fabricated padding or guessed owners. Its measured
Port Forge oracle separates event timing from host presentation and records
coverage limits. SimAnt uses that discipline with DOSBox-X, not Port Forge.

Empires' `tools/build_production.py` stages complete source objects and DATA/BSS,
checks object identity and invokes TLINK once. Its runtime classification and
`docs/current/closure-frontier.md` retain compiler-evidenced ASM, register/IRQ
contracts and opaque internal state. `docs/current/workflow-audit.md` is a
historical migration diagnosis, not a second current build plan. SimAnt reuses
the one-link and explicit-runner ideas, while retaining RTLink overlays, MSC
large-model contracts and its existing stricter source/byte admission rules.
Neither sibling's linker layout, compiler rules nor measured runtime behavior
is imported as a SimAnt fact.

## Classification and acceptance

The former single `SEMANTIC / PORT-BLOCKING` heading combined several different
proof obligations. Current rows carry a reviewed `closure_class`:

| Class | What is missing | Closure criterion |
| --- | --- | --- |
| SOURCE_REQUIRED | A live source owner, lifetime or execution contract | Admit the complete supported contract through `promote.py`. |
| SUPPORTED_DOMAIN | A resource/caller/state bound | Exhaust the pinned resources, close every nominal producer/consumer and retain out-of-domain negative controls. |
| LAYOUT_SENSITIVE | A conditional physical alias with unresolved ordinary observability | Prove supported exclusion or preserve observed behavior; perturbation must actually move the relevant addresses. |
| UNATTRIBUTED_STATE | Ownership, initialization or use of a residual range | A bounded opaque owner is sufficient if independently grounded; otherwise prove runtime ownership or erasure/exclusion. |

Classification is not acceptance. Open rows still refuse canonical linking.
No conditional alias is called historical-only solely because it looks like a
bug. The already reviewed alignment/order residue remains historical-only.
An original allocating TU or surplus historical COMDEF capacity is **not** a
prerequisite for a functional provider with a complete independently proven
supported footprint. This is the existing `storage.json` policy, now applied
to the audio scheduler. Such an allocation must not be reported as the original
capacity, byte-exact physical layout or a guarantee for replacement resources.

The supported evidence domain is the locked SHARED/HCEGANT/SOUND corpus, valid
nominal game control flow and successful relevant resource operations. It does
not cover custom language/display databases, corrupt saves/resources, arbitrary
helper entry states, deep paths overflowing FileSelect, or parser-accepted
`/s9` outside the nine actual device-table entries. These limitations are proof
boundaries, not newly inserted clamps or changes to canonical game algorithms.
Full runtime acceptance still requires boot, VGA, logo/input, simulation, sound,
save/load and sustained play; neither a successful link nor a timeout proves it.

## Material conclusions

* The two scheduler arrays now have an independently reviewed ten-track
  functional footprint: 10 status bytes and ten DOS longs. Initialization
  dominates enabled ISR access, current/best indices remain below the decoded
  track count, and the private status pointer never escapes. The exact game TU
  and 29 strict semantic registrations stay unchanged. The native duplicate
  allocations have been removed.
* The complete corpus has one five-title menu. All title writers and nominal
  keyboard/mouse event readers use 0..4, and the unhooked HARD menu allocation
  remains stable for their lifetime. Two canonical five-word arrays now replace
  the native overlapping allocation and inserted failure branch. Arbitrary
  fabricated events and replacement resources remain outside this proof.
  Window preload IDs are 0..33, the palette copy is exactly 96 bytes, and the
  purge resource covers all 34 iterations. A selected-color value 63 is present,
  but the complete nominal selection-call audit excludes its activation for
  valid shipped object IDs and ordinary saved state. Original event controls
  corroborate that exclusion; dynamic object/ID provenance remains open.
  A concrete counterexample now reaches the object bounds diagnostic: successful
  startup on K: selects index 21 in the 21-object file-selection window. The
  current supported environment does not restrict drives to A..H. This prevents
  inferring every object index from the shipped button range alone.
  It does not disprove independent handle or palette ownership: the high byte
  still selects window 22, and actual first-fatal `Punt` exits before the modeled
  overread. Those owners need their separate dynamic-ID and pointer proofs.
* The default successful VGA database lifetime acquires shared, graphics and
  sound once each. Complete caller, storage and save-table audits preserve slots
  0..2, resolving both slot adjacency gates in this explicit domain. Extra
  language/display packages and returning failures remain excluded and tested.
* That same locked VGA lifetime preserves display mode 8. Both icon helpers
  bypass the mutable icon slot in that mode, even if activated indirectly.
  The [mode and save-state audit](../evidence/canonical/icon-handle-view/vga-review.md)
  closes the two icon-specific gates without admitting a bitmap or changing any
  game function. Mode-2 pointer-load contrasts remain permanent controls.
* The same domain now closes [sound selector dispatch](../evidence/canonical/audio-track-owner/selector-review.md),
  [window callback/rectangle adjacency](../evidence/canonical/window-domain/array-gate-review.md),
  and the [critical selector aliases](../evidence/canonical/error-continuation/selector-review.md).
  Complete producer, alias and save audits compose the existing bounds; original
  out-of-domain stores remain regression controls. Four semantic gates remain:
  ctype prefix reads, clip generation, viewport dimensions and the FileSelect
  local path. 44 unattributed bytes remain unresolved.
* Every storage import now has a canonical owner. The last one, the
  [clip rectangle destination](../evidence/canonical/clip-owner/review.md), is
  256 records: each writer copies one sentinel-terminated list after a
  256-record overflow check, or from a list already bounded by one. Original
  255/256 controls and a returning-`Punt` 2,056-byte contrast are retained;
  generation before the check can still overrun its heap temporary, so the
  clip gate stays open. The native reservation rewrite is retired.
* `Punt` returns for a nonzero reentrancy guard. The permanent original-instruction
  witness reaches the real database `record[-1]` copy with four occupied slots
  and that guard. This globally rejects the tempting `noreturn` shortcut; it does
  not claim the combined failure state occurs in ordinary play.
* Real DOSBox-X execution of the canonical path helper disproves unconditional
  filename safety: a valid deep DOS path succeeds but needs more than the
  67-byte local buffer. The import remains open with a concrete domain limit.
* Real RTLink's extended library dictionary pulled a competing CRT `_ffree`.
  The documented `NOEXTDICTIONARY` option resolves it using unchanged canonical
  objects and libraries. The source call targets its canonical definition;
  the old warning acknowledgment has been removed. A real period-tool negative
  control restores the collision with `EXTDICTIONARY`.
* Default RTLink vectors also redirected the display dispatch tables through
  its loader, contrary to the original direct-pointer contract. A timer cursor
  callback could then re-enter the loader before an interrupted S06 load set
  its in-memory flag. Explicit symbolic vector selection restores direct driver
  callbacks while preserving the required game loading vectors. A real compiler/
  linker regression checks callback pointers and both canonical and alias calls;
  restoring automatic vectors fails the new postlink policy check.

## Diagnostic execution and the remaining route

`dos/diagnostic.py` accepts explicit, hash-pinned storage candidates only from
ignored worker/scratch directories. They must supply exactly the undefined
imports and no code, imports or fixups. It preserves all unresolved contracts,
uses unchanged canonical objects and pinned libraries, and emits a
`DIAGNOSTIC_DOS` receipt with `closure_eligible=false`. `dos/build.py` retains its
canonical refusal. The shared linker stage invokes real RTLink once and checks
its diagnostics; no object/image patch or original game-byte fallback exists.

`dos/run.py --original` and `--build-report` launch separate pinned DOSBox-X
sessions and copy only locked runtime files. STARTED means the batch reached
the invocation, not that game initialization completed. Time limits grant no
functional milestone. MS-DOS Player remains appropriate for compatible small
historical helpers; MSC 6.00AX and RTLink retain their evidenced DOSBox-X runner.

The [diagnostic receipt](../evidence/canonical/diagnostic-link/receipt.json)
records the earlier 193 canonical objects and seven provisional owners.
Reversing provisional COMDEF order did not change allocation; initialized
providers move the actual addresses. Short startup traces agree through VGA
entry. Longer input/video replay reaches Full Game in original DOS and diagnostic
layouts, but repeated runs of an unchanged compact provisional image also expose
INT6, a segment-limit loop, or an explicit game abort. These runs do not establish
deterministic replay or a fault caused by storage placement.

A host snapshot of one INT6 failure isolates an incorrectly relocated S06:
all 119 distinct relocation words contain twice the load-base adjustment, while
all 9,346 other bytes match disk. A successful snapshot of the same executable
contains the correct single adjustment. Every provisional spider byte is still
zero in the captured failure. The larger 6,276-byte provider remains a measured
access lower bound, not a demonstrated fix. The
[runtime observation](../evidence/canonical/diagnostic-link/overlay-relocation.json)
pins both snapshots and a known-register decoder control. The
[vector contract](../evidence/canonical/diagnostic-link/overlay-vectors.json)
records the concrete interrupt reentry path and its correction. This is a static
explanation consistent with the captured failure, not an instruction trace of
the interrupt instant. The earlier unsnapshotted failures are not automatically
assigned the same cause. Corrected COMDEF and initialized-storage diagnostic
links retain all seven provisional owners.
No screen match grants storage admission, sound output or complete
simulation-state equivalence.

The subsequent [Save/Load observation](../evidence/canonical/diagnostic-link/save-load.json)
records 307 writes totaling 48,386 bytes and a visible successful-save dialog in
both executables. Both also load the identical original save through the DOS
file chooser, issue all 307 expected reads and return to a paused Full Game
screen with matching visible terrain. This is a bounded compatibility check;
all restored bytes, the reverse file direction and longer play remain unproved.
Repeated selection controls abort in both original and source. The
[lock investigation](../evidence/canonical/diagnostic-link/load-lock.json)
proves an original conditional list-selection lock leak, but the actual failing
row and lock slot were not captured. The printed number is an omitted vararg,
not a reliable window ID. No reconstruction patch is justified by that symptom.

The [RNG audit](../evidence/canonical/diagnostic-link/rng-domain.json) confirms
tick-based startup seeds and per-yard generation seeds. Matching clock samples
and call histories reproduce the yard seed table; changing either changes it.
Saves preserve yard seeds and world data but omit both live RNG states. Different
fresh worlds or subsequent random outcomes are therefore not evidence of a
defect without controlled seeds, state and call history.

Next, extend restored-state and longer gameplay checks with the corrected linker
contract on the canonical-only link, and close the clip generation, viewport and
FileSelect domains and the residual data ranges. Preserve the
CRT signed-prefix question until observed or statically excluded in that domain.
Icon loads are now excluded in the existing default VGA domain; other display
modes remain outside that proof. Only then use the three-way DOS-original/DOS-source/
SDL comparison to choose between canonical reconstruction and platform fixes.

The [canonical-only diagnostic](../evidence/canonical/diagnostic-link/canonical-only.json)
links all 200 canonical TUs with an empty provider manifest: no provisional
storage remains. Its 40-second replay reaches SimAnt - Full Game with zero
reported guest faults. The four gates and 44 data-debt bytes still refuse the
canonical link; this bounded observation is not gameplay or sound acceptance.

The [clip-generation control](../evidence/canonical/clip-domain/review.md) rejects
the window-count capacity argument. Synthetic 31-window geometry produces 256
disjoint rectangles in the original caller; the rectangle helper writes its
sentinel at displacement 2050 of the 2048-byte temporary before entering the
overflow diagnostic. A 29-window control produces 225 rectangles and completes
without crossing either scratch guard. These controls do not prove shipped UI
reachability or admit the separate fixed clip destination. Complete geometry
and repeated-producer bounds before emission remain the next clipping obligation.

The 44 residual bytes remain explicit: 4 at 56FE, 2 at 5A28, 5 at 5A96,
18 at 60B0, 14 at 79F0 and one common-tail boundary byte. The hot-box-shaped
18-byte range has a real symbolic callback but no independent declaration/use
bridge; the CRT 14-byte range has observable conditional signed-prefix reads;
the other ranges need bounded ownership or startup/observer evidence. Naming
every byte is unnecessary, but zero contents or an absent literal reference
cannot supply the missing proof. None is silently erased by this phase.
