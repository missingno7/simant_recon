# Portable handle allocation boundary

`handles.c` is the whole-program host owner for source-visible Ralloc handles. It replaces paragraph/EMS/MCB placement with host allocations while preserving observable handle behavior: a stable `char **` master pointer, mutable data address, requested size, type, lock depth, attributes, age, and a 12-character name. The normal handle master pointer is a real native address. The DOS `0F0F:index` form is represented as an opaque `uintptr_t` tag and normalized through the slot table before any lookup; it is never dereferenced.

`SimHandleManager` is the testable contract surface. It enforces nonzero positive sizes, type range, lock depth 100, lock-sensitive free/resize/discard, data preservation through resize, oldest-unlocked-soft eviction under its configured byte budget, and persistent discarded handles whose data cannot be locked. Host addresses can move; master-pointer identities remain stable. `dos_malloc(uint16_t)` matches the source one-word ABI; the internal named allocation helper is used by `f_171C_2190`. `dos_realloc(void *, uint16_t)` and its source wrapper `f_171C_2302(void *, uint16_t)`, plus `dos_free`, keep an explicit base-pointer-to-handle registry, so free/realloc never try to infer a handle by subtracting DOS-style block headers.

Implemented source-named external entry points are the used high-level allocation, pointer/lock/unlock, free, size/type/age, resize, discard-all-soft, and allocation-statistics APIs declared in `handles.h`. The three called `2CFB` thunks forward to their source-anchored `171C` targets. Unsupported EMS detection reports false because there is no EMS region. A host compaction call reports no move because host allocations are not paragraph-segmented. The default global manager is uncapped; its free-capacity query returns `-1` (unknown) unless the embedding host configures an explicit capacity with `sim_handles_global_configure`.

This is a portable platform implementation and a native contract test, not an original-DOS differential and not evidence for a new `BEHAVIOR_EXACT` claim. The original memory manager’s `Punt` calls are nonreturning failure boundaries. Native symbol wrappers fail closed through null/zero/unchanged results plus `sim_handles_global_last_status`; callers that depend on the exact DOS termination/UI path remain unsupported until that host boundary is modeled. Paragraph heap search/split/coalesce (`f_171C_0EEA`, `f_171C_0FBC`, `f_171C_068C`, `f_171C_0160`), relocation/compaction internals (`f_171C_0ADC`, `f_171C_0CF4`), EMS initialization and runtime shutdown are intentionally retired rather than replaced with guessed success paths. No `f_171C_0CF4` / `f_171C_0FBC` fake definitions are exported.

The bounded directed and seeded randomized tests (2,000 deterministic LCG-selected operations) live in `portable/tests/whole_program/platform/handles_test.c`. They exercise lock misuse, handle-index normalization, resize content retention, explicit discard, soft eviction, hard-budget failure paths, pointer-to-handle free/realloc, and repeated valid operation sequences. They verify this native API contract only.

The source dump entry f_171C_030C appends a logical native handle inventory to ralloc.dmp, including payload sizes, types, locks, ages and names. It does not claim the DOS paragraph-map format. The actual source CloseIndex free(payload) route is supported by the shared allocation registry.
