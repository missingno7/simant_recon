# StopSong dependency diagnostics

`evidence/dependencies-v4.json` records two resource-release scenarios and two
channel scans against the original DOS implementation, exact MSC candidates,
and an isolated native contract model. Real same-module enqueue/flush bodies
execute in both DOS lanes. Allocator, database release, timer/device leaves, and
the called channel-release body remain explicit boundaries. This packet does
not establish full sound playback or production integration.

The captured runner pins its inputs before compilation and after execution.
Review found all 60 paths in each snapshot unchanged. Its fixed output path is
write-once and it refuses to replace the captured V4 report. A future execution
must use a separately archived runner version and fresh output path.

V1–V3 receipts retain earlier diagnostics. Their predecessor runner/model
sources were not archived with those receipts, so their original hashes and
outputs remain evidence of the captured attempts but cannot be reproduced from
the V4 runner. They are not current acceptance evidence.

The native model is a test tool. Production audio conversion must retain the
recovered source bodies and replace hardware leaves through explicit services.
