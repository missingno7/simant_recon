# Residue controls after FileSelect

These whole-module searches are retained to prevent repeated experiments. They
are diagnostics, not acceptance. `index.json` summarizes 181 series and 7,203
variants; individual JSON files retain claim/data/order verdicts without object
bytes or lengthy compiler transcripts. Scripts use the current workspace paths;
their inputs may have changed since execution, so inspect the recorded base first.

The four exact rows in `freeblock-next.json` are alternative expressions for the
same 362-byte function, `f_171C_0160`. The unsigned-word segment plus unsigned-long
paragraph count was freshly rechecked and promoted through `promote.py`.
`WIDTH-1` records whole-module positive and negative controls. Two exact `bars-rectangle-stages.json` rows recover DrawColonyBars; the freshly
merged and renamed source passed promotion and full validation. Its positive,
negative and acceptance transcripts are in `../colony-bars/`. Other retained
series did not pass an exact acceptance gate. A shorter distance remains debt.

The main negative findings are:

* S15: declaration permutations, pointer types, font temporaries and folded reads
  still leave the text-pointer segment's two operand bytes wrong.
* CalcScore: combined folded index reads and local-lvalue casts do not resolve
  the index/accumulator home swap. Unsigned alias diagnostics can change signed
  loop semantics and must not be accepted on similarity.
* S17: parameter widths do not resolve the pointer/hidden-spill frame layout.
  `s17-parameter-width-v0.c` is the current-module merge of the natural 266-byte
  body; it remains unclaimed.
* Map drawing, DisplayCard, the window-index helper and EnterNest: tested register,
  typed-view, iterator and real-declaration variants remain inexact.
* The list-string helper, Tandy channel output and MIDI word reader remain
  inexact under the recorded natural-expression and folded-read trials.
* New trials of memory-helper result assignments, window-rectangle destinations,
  ant-direction result/working locals and typed paragraph-address calculations
  did not close additional functions.
* SpiderScan counter dependencies and volatile declarations do not reproduce
  its otherwise matching body with the extra original zero initialization.
* Text rendering: a correctly updated byte cache preserves space skipping and
  improves the diagnostic result, but still misses register allocation, the
  hidden byte home and font-height storage. Signed-char ranges, byte views and
  loop-lifetime controls remain inexact. `printstyle-loop-cache-v7.c` is an
  unclaimed 1,035-byte source against the 1,039-byte target.
* Memory compaction: the reviewed resJ control flow and WIDTH-1-style next-block
  sum reproduce all 490 bytes of length. A wide Boolean result read through its
  low word leaves six differing stack-home bytes; all prior claims and data
  remain exact. `memcf4-result-lifetime-v6.c` is retained as an unclaimed
  hypothesis. A union with an unused wide member gets close but is not a valid
  explanation of the source layout; it has not been accepted.
* The question dialog's scalar coordinates and separate loop counters narrow
  the discrepancy to initialization and loop operand/layout choices. The
  retained `question-loop-order-v2.c` is 653 bytes against 649, still inexact.
  The coordinate search was corrected to advance each loop index exactly once
  before retaining its results.
* Window-unlock pointer/address/segment-offset forms, AdLib staged byte
  attenuation, and yard-patch register/expression orders remain inexact.

Do not promote the historical `full-search/f_171C_0ADC/best.c`: its `int val2`
temporary truncates a far pointer. That generic search hypothesis is semantically
unsound. Current trials use the canonical correctly typed pointer expression.
Likewise, diagnostic width changes and discarded local stores need semantic
review even when their instruction distance improves.
The old `full-search/win_PrintStyleTextInRect/best.c` caches a character before
the space-skipping loop without updating it as the index advances. It can loop
forever on a space and must not be promoted. The later loop-cache controls do
update the character on every iteration.

`ant1686-result-flow-v18.c` is a 511-byte near result with a separate returned
local. It matches more register behavior but still misses the 516-byte target,
frame layout and control flow. It is preserved only as a source hypothesis.

No assembly workaround, original-byte capsule, object patch or extent trimming
was used. Linker debt is independent of these game-code searches.

* Map tile drawing: a used row-coordinate copy matches all but the first sum's
  destination register and the resulting one-byte shift. It remains 265 vs 264
  bytes; the preserved coordinate-copy source is unclaimed. Width, pointer,
  branch-flow, parameter-reuse and optimization controls did not close it.
* LessonDone: the embedded switch table makes a naive linear disassembly score
  unreliable. The body-aware helper skips the known table only for diagnostic
  ranking; the acceptance gate still checks every byte, fixup and relocation.
  Shared labels, grouped cases, negative guards and Boolean returns remain
  inexact. No acceptance mask was introduced.
* S15 combined pointer reads and result types, S17 used wide locals, and memory
  compaction's combined result reads leave their respective home/frame residues.
* DrawColonyBars's rectangle-field staging is accepted. Coordinate-width and
  local-stage variants alone were inexact. InvertPatch's parameter reuse,
  explicit products and local optimizer controls remain inexact.
* History graph: a 20-byte buffer, cached global reads, and two-word state
  aggregates are tested hypotheses, still inexact. The aggregate series was
  corrected to use its cached count in the loop before retaining results.

  Wide result controls preserve signed low-word comparisons and varargs width.
