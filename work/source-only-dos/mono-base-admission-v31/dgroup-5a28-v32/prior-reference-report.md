## Three-byte common-tail overlap

The bytes `72 24 E7` at file range `[506253,506256)` are the final three bytes inside the S27 section extent and simultaneously the start of a 256-byte `debt:common_tail` file-tail region. Immediately before them, provenance identifies `chksum.asm/MSG`, `crt0msg.asm/PAD`, and `nmsghdr.asm/EPAD`; the `EPAD` contribution ends at file offset `506253`. The remaining 253 tail bytes lie beyond the S27 section image. `tools/link.py` treats the entire tail region as unresolved common tail, not generated fill. There is no game function/data reference evidence for these three bytes.

This is a linker/file-boundary question, not established game state. The port does not need the trailing bytes once the DOS load-image boundary is preserved as oracle metadata. Keep all three historical bytes unresolved until the common-tail mechanism is proved; do not reclassify them as harmless from their position or bit pattern.

## Closure assessment

Semantic questions have strong answers for `2100`, `5A96`'s referenced fields, and `68AC`; the `60B0` timer-shaped record is a plausible but unproven live object. The 12-byte FAR_DATA gap, `56FE`, `5A28`, and three-byte tail have no evidenced game behavior. The `79F0` span has a concrete MSC library member match but still needs historical member-selection proof. None of these findings authorizes a provenance rewrite, data promotion, or a claim of zero unresolved game-data bytes.
