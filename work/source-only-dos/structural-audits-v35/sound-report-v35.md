# Shipped SOUND song-domain audit (v35)

Disposition: **resource/parser facts confirmed for the supplied `SOUND` pair; no free-list capacity or normal-run schedule claim.** This is a read-only domain pass for `fd_50F6_0150` append/reachability. It reads only the shipped sound resources and accepted/effective DOS sources; it does not build or run the game, write canonical source/layout, or save decoded resource strings or payload bytes.

## Source and resource interpretation

`OpenIndex` reads a 20-byte header followed by exactly `count * 8` index bytes. The pinned `SOUND.NDX` has 120 entries (the source-read prefix is 980 bytes) and a further 256 bytes that this code does not read. The rows are 57 PCM (kind 5), 33 SONG (kind `0x12`) and 30 MIDI (kind `0x14`). Every row has index flags `8`; `DBRecall` tests bit 0 for its packed branch, so these records are copied directly. For song and MIDI data, the 10-byte record header is at DAT offset +14 and payload at +24. `f_0000_0000` only changes kind-5 PCM samples; it does not alter the kind-`0x12` or kind-`0x14` payloads.

I followed the accepted player source rather than a generic MIDI decoder. Kind-`0x12` header word 0 selects the MIDI object after the source's byte swap; word 3 supplies its note transpose. All 33 song headers name an existing stream; there are 30 distinct streams. Three headers alias two streams: `0x2B06`/`0x2B07` use `0x2B05` with transpose +6/+12, and `0x2B09` uses `0x2B08` with transpose +12. The other 30 records use identity stream IDs and zero transpose.

The stream pass follows `f_284A_0256`, `_0199`, `_01D5`, `_038F`, `_0537`, `_05C5`, `_0673`, and `_067F`: big-endian header/track lengths, the source's variable-length delta reader, running status, per-track time accumulation, minimum-time track selection, and source tempo scaling. It uses `type = (status & 0x70) >> 4` and the actual seven-entry `g_75A4` length table. The callback loops while `f_284A_038F` returns exactly zero (and song state is not ended); any nonzero signed-16 return, including a negative return, exits it. It does not assume the unreachable `case 12` is a program-change implementation; type 7 remains an explicit table-overread boundary.

All 30 streams have 2–10 tracks and each declared MTrk extent ends within the resource; together the declared tracks end exactly at payload end (zero bytes after the final declared MTrk). Replay reaches an EOT event in each of the 116 tracks and finishes without a status-7 table overread, track-boundary read, or other parser warning. This is not byte-for-byte cursor consumption: `f_284A_05C5` sees EOT type `0x2f`, sets the track status to `0x2f`, then backs the cursor to the preceding `0xff`; it never reads that meta event's zero length. Across all streams, 348 bytes remain from those backed-up EOT status cursors to their MTrk ends (three bytes per track), including 116 unread zero-length bytes. There are no type-4 events; the two type-3 events only advance through the source's two-byte event path.

Across the 30 distinct streams the parser dispatches 7,832 source note-event actions: 152 type-0 events and 7,680 type-1 events. Every note channel in these resources is below 14, so each such event calls `f_284A_04C9` once. This helper then calls either `f_295C_02E8` when volume-scaled velocity is zero or `f_295C_01EC` when it is nonzero; the latter allocator-call count is not fixed by resource bytes alone. Of the type-1 events, 3,916 have nonzero raw velocity, 3,764 have raw velocity zero, and two of the nonzero velocities equal 1. At the global initializer volume `g_7570=127`, those two velocity-1 events scale to zero; 3,914 type-1 events scale nonzero. `f_284A_024B` can change `g_7570`, and the runtime volume at each event is unproved. Only channels 0–10 carry these events; channels 11–13 are silent in this resource set.

The longest source-replayed immediate callback is 14 dispatched events, tied by streams `0x2711` and `0x2718`. The largest source note-event-action burst is five, found in `0x2711`, `0x2718`, `0x2AFC` and `0x2AFD`. For `0x2711`, the 14-dispatch burst contains two note-event actions; a separate five-action burst contains three raw note-off-class events and two nonzero-velocity type-1 events. These are deterministic bounds over this resource set and the accepted parser/scheduler. One `f_284A_04C9` note-event action is not necessarily an `f_295C_01EC` allocation call, since scaled velocity can route to `_02E8`. The bursts do not establish callback timing against the main-loop drain.

The correction models signed-32 VLQ/track-time arithmetic, signed-32 `scale * delta`, arithmetic shift, and signed-16 narrowing of the `_038F` return. Across the resources there are no signed-32 product or track-time overflows, no negative or zero-vs-nonzero boundary disagreements against the earlier unbounded/positive-wait replay, and all 6,605 callback boundaries match; dispatch/action extrema are unchanged. The maximum absolute unwrapped product is 296,730, and the largest absolute accumulated track time is 88,390. Tempo is at most 500,000 (including the source default); the largest `tempo / 1000 * 1194` intermediate is 597,000 and resulting scale is 47–127, all well within signed-32 range. VLQs are at most three bytes / 88,320. The maximum source `int` cursor/address is 8,719, within signed-16 range; no offset wrap is exercised by these streams.

## Fixed song selector and SFX facts

The accepted data-only module `data:55B3@0064` holds the single 14-channel `Song` descriptor used by `f_284A_0013` for every requested song. A successful `f_0000_0193` load copies its bank and program arrays, then visits all 14 banks. In selector modes 1 and 7, every descriptor bank is `SND_DAC`; each referenced sample object exists as a kind-5 SOUND record. The program word is passed to the voice allocator as **priority**, while the bank word selects the device/instrument row. No song program update is present in the payloads, and source type 12 is impossible under the mask.

`channel: bank/device / program-priority / mode-1 sample object / mode-7 sample object`

`0: 0/0/35/0; 1: 25/7/56/25; 2: 53/7/56/53; 3: 3/7/56/3; 4: 54/7/56/54; 5: 35/5/35/35; 6: 46/5/35/46; 7: 50/5/35/50; 8: 51/5/35/51; 9: 48/5/35/48; 10: 0/5/35/0; 11: 12/5/12/12; 12: 43/5/43/43; 13: 52/5/52/52.`

Thus the descriptor's loaded sample-object set is `{12,35,43,52,56}` in mode 1 and `{0,3,12,25,35,43,46,48,50,51,52,53,54}` in mode 7. Neither overlaps sample object 18 or 47. SFX table row 18 is note 60, priority 2, device 18, velocity 127; row 47 is note 60, priority 3, device 47, velocity 127. The selected rows in both the mode-1 (`0C42`) and mode-7 (`0EE2`) instrument tables are DAC and point to sample objects 18 and 47 respectively. The priority allocator rejects priority below 1 and only takes a voice when the incoming priority is at least the best current channel priority; therefore priorities 2/3 can use an idle DAC voice but cannot replace an occupied priority-5/7 song voice.

This confirms the important conditional distinction: song banks preloaded by a successful mode-1/7 song are loaded as state 2; the dig and spider-foot SFX use distinct state-1-capable sample objects. Song-note replacement alone cannot append those preloaded song samples under the `loaded == 1` release guards. A song event can still replace or release a distinct SFX owner if the allocator selects that voice. Each immediate callback has at most five source note-event actions in this resource set, and those actions call `f_284A_04C9` once on the resource-used channels. They do not imply five `f_295C_01EC` allocator starts: type-0 events, type-1 zero-velocity events, and any type-1 event whose volume-scaled velocity becomes zero call `f_295C_02E8` instead. One note-event action can sweep several idle DAC channels, and one note-off can match multiple voices. The event-burst count therefore does not directly bound append count or establish count-39 reachability across callbacks.

On a stop/reload path, the same fixed descriptor makes `f_0000_039B` visit 14 kind-1 bank slots in these modes. Those slots include repeated sample pointers (for example, mode 1 has seven slots referring to object 35 and four to object 56). If that cleanup occurs while `g_7574 != 0`, the writer can append repeated pointers without draining; this is a source/resource conditional count, not evidence that the interrupt timing reaches it. Sound word 2 starts enabled and the menu can toggle it (v34 correction). Voice occupancy, chosen channels, interrupt/main-loop ordering, the physical free-list extent and normal-run count-39 reachability remain open.

## Reconciliation note

The v33 prose says dig SFX row 18 is not a mode-7 DAC case. The current pinned accepted sources show the opposite: selector 7 dispatches to `f_277E_0760`, which copies `fd_55B3_0EE2`, and row 18 of that table is `SND_DAC` pointing to sample object 18. The source path also passes the SFX row's second word as priority and third word as device. This audit flags that earlier statement for root reconciliation; it does not infer that the voice is selected at runtime.
