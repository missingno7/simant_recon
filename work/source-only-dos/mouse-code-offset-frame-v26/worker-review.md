# root:1B73 callback-offset frame review (v29)

**Disposition:** `root_reviewed: false`. This is a scratch evidence packet, not an admission or source change. Scope is the five same-module code-label `LEA` fixups in `root:1B73`.

The probe reconstructs the generated TU from canonical `src/root/m1B73.asm` using the pinned source-bindings, assembly-frame-bindings and dgroup-rect-frame-bindings packets, in that order. After line-ending normalization it matches `build/source-only-dos/sources/U087.asm` exactly. Reassembling the baseline with pinned MASM 5.10 reproduces admitted `U087.OBJ` exactly (8,751 bytes; SHA-256 `557405d3d81b2b99965385dd70ff55aa77e71fe2515b3344fa9fc2618026a4df`). Canonical source SHA-256: `3097a6b03ff1d8bdfa7d573632d9905de88d754c8b1e047de4014c4f186cb848`.

The read-only disassembly packet came from `python tools/context.py f_1B73_0235` without `--raw`. At canonical source lines 494, 504, 511 and 518, `f_1B73_0235` forms offsets for `_f_1B73_03EE`, `_f_1B73_065A`, `_f_1B73_06E3` and `_f_1B73_051F`. The first follows `push cs; pop es` and INT 33h function 0Ch, whose callback address is ES:DX. Before INT 21h function 25h, DS is set to CS; the next three callback addresses are DS:DX. Those four targets are same-module FAR procedures (source lines 690, 850, 981, 1037). At line 1531, the fifth LEA forms `_f_1B73_0CB3`'s offset, which is stored word-sized into `_g_5FFA` and later used by `call word ptr _g_5FFA` at line 775. `_f_1B73_0CB3` is a same-module NEAR procedure (line 1800). The canonical extern declaration spells `_g_5FFA:byte`; this finding relies only on the actual word-store/near-call use chain and makes no claim about that external object's wider allocation.

The complete-module MASM comparison shows that replacing all five `lea reg, ds:label` operands with natural `lea reg, label` preserves `MOUSE_TEXT` length `0xEF6`, its entire segment byte stream, all 440 fixups except the five frame fields, and every segment definition, public, group, external and local symbol. Exactly these fixup sites change from frame `DGROUP` to `MOUSE_TEXT`: `024E`, `0269`, `0281`, `0299`, `0AB2`. Their segment-relative target displacements stay `03E8`, `0654`, `06DD`, `0519`, `0CAD`. The explicit `cs:label` spelling yields the same object bytes and five frame corrections. The listings retain plain `8D 16`/`8D 06` LEAs; no segment override prefix is emitted. `LEA` computes an offset, and the operand's explicit `ds:` spelling selects an OMF frame that is wrong for these code offsets.

The `mov reg, offset label` and `mov reg, offset MOUSE_TEXT:label` controls are rejected. Each shortens the segment from `0xEF6` to `0xEF0`: five 4-byte LEAs become 3-byte MOV immediates, and the existing `even` before `_f_1B73_0D4C` no longer emits its one-byte pad. That also shifts subsequent labels/fixup positions, so MOV is not a frame-only correction.

A separate fixture assembled from test-owned source checks these ABI shapes under RTLink 4.00 and 6.10. Its 16-byte PREFIX starts at DGROUP offset `0x42`; `_prefix_end` and `_DATA` start at `0x52`. `CALLBACK_TEXT` is outside DGROUP. The correct natural-frame executable checks ES=CS and DX=the mouse code offset, DS=CS and DX=each of three vector code offsets, then stores the local callback offset in a typed word and near-calls it. Both natural-frame links are warning-free and return `PASS`. The wrong-DGROUP-frame control returns `FAIL` under each profile. Its first test is the mouse LEA/offset comparison: the listing branches on mismatch at `CALLBACK_TEXT:000D`, before any callback call (the local near call is at offset `0065`), so the negative never calls a bad callback. RTLink 6.10 emits five WRT0082 illegal-fixup warnings for that intentionally wrong frame because `CALLBACK_TEXT` is before DGROUP. That one test-only negative executable was run to confirm its expected FAIL; it is not a game image. The other three fixture links have no warnings. Complete MAP, LINK.LOG, RUN.LOG and EXE files are preserved and individually pinned.
