## Source dataflow and boundaries

The exact-symbol audit of canonical sources is limited to the eleven files containing these names: `src/root/m1E57.c`, `m1D8E.c`, `m21FA.c`, `m1C62.c`, `m1B73.asm`; `src/S10/m35F5.c`; `src/S22/m39C7.c`; and the display drivers `src/S00/m31AD.asm`, `src/S01/m3126.asm`, `src/S02/m3126.asm`, `src/S03/m3126.asm`. The probe records line-numbered occurrences for those explicit files.

- `m1E57.c` is the mutable owner API: `clip_SetWin`, `f_1E57_0296`, and include/exclude operations point at locked clip data or `fd_50F6_3C14`; `f_1E57_0351` points at `&g_5A9C`; `clip_Off` clears the pointer. Lists advance by `sizeof(Rect)` and stop when `top == (int)0x8000`.
- `clip_Push` saves the prior pointer identity and copies the list into its stack node. `clip_Pop` restores or clears that state and may copy a popped list back to `fd_50F6_3C14`. This is a mutable list head with a source-visible save/copy/restore lifetime, not a never-changing global.
- `m1D8E.c` performs eight complete Rect-list traversals. `m21FA.c` and `S22/m39C7.c` use `int far *` views and element `[1]` for the same sentinel `top` field at target offset `+2`.
- `S10/m35F5.c` saves the pointer through a `char far *` view, clears it during menu drawing, and restores it; it does not dereference that view. `m1C62.c` clears the pointer on alert paths.
- `m1B73.asm` saves both pointer words, temporarily writes the screen-Rect pointer for a display callback, and restores both words. S00 reads the high word and loads the full pointer with `lds`; S01–S03 read the high-word alias. The drivers contain reads, not alternate pointer stores.
