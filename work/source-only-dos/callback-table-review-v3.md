# Callback table ownership review v3

Root admitted one naturally typed, zero-initialized near table as the source-functional storage owner for the 25 four-byte slots at `0x9128..0x918B`. It does not claim a historical COMDEF owner or translation-unit order. The provider source is exactly `void (far * near driver_callback_table[25])();` in [callback-table.c](providers/callback-table.c); the per-slot source/xref/dispatch map and reviewed contract are in [callback-table-reviewed-contract-v1.json](callback-table-reviewed-contract-v1.json). Probe outputs and candidate contracts are confined to ignored `build/workers/dos_callback_table_runtime`.

The extent follows source operations: canonical m1B4E reset iterates `0x19` times and writes two words per slot; copy transfers `0x32` words; S00–S03 each have 25 dword dispatch entries. MSC 6.00AX `/AL /Os /Zi` emits one near COMDEF named `_driver_callback_table`, length 100, with zero-length CODE, DATA, CONST, and BSS segments. Its only nonempty segments are compiler debug metadata. The owner array gives a four-byte period without inventing per-slot struct fields or callable signatures. The source map records all 25 positions: 23 registered layout names plus test-only aliases for the two unnamed positions, slots 13 and 22.

The self-contained probe freshly compiles/assembles every fixture object from its embedded C/ASM inputs and the provider source, links and runs under both pinned RTLink versions, and records the exact expected and observed result for all eight cases. Both positive cases pass, as do the expected negative results for `_g_9188` at `+94` instead of `+96`, a nonzero-initialized owner, and `_g_3DF8` pointing at `_g_9128+4`. Runtime checks cover all 25 alias offsets, zero initialization, reset/copy extent, first and last entries, byte/word overlap, and canaries. The 23 alias names come from non-null `layout/symbols.json` rows joined to direct identifier occurrences in canonical `src/**/*.c` and `src/**/*.asm`; the ignored source-only build report and its import/declaration metadata are intentionally not loaded or needed.

The positive maps show the linker's shifted DGROUP placement: DGROUP is segment `0x01A3`; `_driver_callback_table` and `_g_9128` are both `01A3:07A0`; each subsequent alias is four bytes later through `_g_9188` at `01A3:0800`. The symbolic pointer field `_g_3DF8` is at `01A3:030C` in the same DGROUP segment. Its runtime offset-and-segment comparison succeeds for both linkers, proving that the existing symbolic pointer relocates to the near owner under a shifted layout rather than relying on historical absolute address `0x9128`.

I also freshly assembled canonical `src/root/m1B4E.asm`. It already contains `extrn _g_9128:byte` and `_g_3DF8 dd _g_9128`, so no initializer edit or separate numeric-to-symbolic control is warranted. In the OMF, `_DATA` belongs to DGROUP, `_g_3DF8` is `_DATA:0x00D8` (offset 216), and its four-byte `pointer32` fixup targets external `_g_9128` with displacement zero. The OMF's pre-link field bytes are `00000000`; the fixture's linked map and runtime word/segment comparison verify the relocation. A source-derived `_g_9128+4` negative leaves segment bytes, publics, groups, externals, and segment definitions identical and changes only this fixup displacement from 0 to 4.

Canonical sources, layout and promotion records remain unchanged. The contract pins the source, provider, tools and runtimes and reports zero oracle-input reads. Production compiles the exact data-only declaration without debug emission (`/AL /Os /Gs`), verifies one near 100-byte COMDEF and rejects any code, initialized data, publics, fixups or extra allocation. The runtime probe uses `/Zi`; its extra debug metadata does not affect the measured storage. SOURCE_ONLY_DOS binds the 23 registered views only within this object and checks the selected linker/runtime contract. Wider driver SS/ES dependencies remain separate gates.
