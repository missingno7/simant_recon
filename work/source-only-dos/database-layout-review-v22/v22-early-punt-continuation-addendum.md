# v22 early-Punt continuation addendum

Classification: `ROOT_FALSE_STATIC_ADDENDUM`; both database gates remain `UNRESOLVED`. This is an additive wording correction to the pinned v22 static-closure receipt. The earlier receipt and executed observations are preserved verbatim. It supersedes only the implication that an ordinary return from the first early callback lets `Punt` return to startup. The broader v17 first-Punt/nonreturn statement remains historical, superseded research and is not current admission authority.

`Punt` sets its private guard, formats/prints the fatal text, then invokes `g_9128(0, 15, 0)` before calling `f_1CE2_01C3` and `o15_384C_0152`. Before `IBMInitStuff` reaches `f_205F_0004`, the source-owned callback table has not been reset by `f_1B4E_0025`; its admitted zero-startup contract makes the `g_9128` far pointer zero. A bare, ABI-correct far return from that call resumes at the following `f_1CE2_01C3` call. By itself it cannot bypass the text helper or return the first `Punt` to its database caller.

The continuation is not yet proved to be an ordinary returning path. `f_1CE2_01C3` formats nonempty text and calls `f_24AB_038D`. Its source-initialized-null font pointer selects `f_1FBD_0000`'s raster fallback. Before display setup, the display fields read by that fallback have not received driver setup (`g_3DD6`, `g_3DDA`, and `g_3DDC` begin at zero; `g_3DDE` begins at eight). The fallback emits through `g_9154`; in the `/d2` branch, `f_1B4E_0081` reaches the same callback per character through `f_1B4E_0110`. `g_9154` is callback-table slot 11 (byte offset `0x2c` from `g_9128`) and is also zero before the callback-table reset. Thus a normal return from the first zero-target call is followed by a second source-zero indirect call on the nonempty-text path. No source, owner, or execution evidence here specifies how either execution of `0000:0000` as code behaves or establishes that the rendering helper preserves its caller's control state.

Conditioned on ordinary declared returns and ABI/control-state preservation by both indirect calls and the intervening helpers, source control reaches `o15_384C_0152`. Every `g_2BD4` switch case falls through to its unconditional C `exit(0)`; the branch changes cleanup performed before the exit, not the terminal path. The existing standalone MSC/RTLink control supports C `exit` termination, while not exercising either invalid zero-target call or the game fatal integration. Therefore all accounted ordinary-return continuations terminate. This does not establish an actual first-`Punt` return to startup, nor does it prove the behavior of the invalid zero-target executions. No counterexample was observed, no arbitrary memory corruption is asserted, and no physical IVT bytes were read.

The specifically missing pre-display state is the callback/display/font setup that follows the earlier language/shared/optional-`lrshare` database opens in `IBMInitStuff`. The known `Punt` guard write and fatal formatting/printing precede the zero callback. The missing evidence is a semantic and stack/state contract for executing the zero far targets and, consequently, for returning through the still-uninitialized raster callback path. This is distinct from the bounded fifth-sound-open path, which assumes all four predecessor opens return successfully and no earlier first `Punt` occurs; it is also distinct from the post-init `/s9` layout issue and from the real timer-restore side effects documented in the v22 receipt.

This addendum introduces no callback initializer, new slot, padding, no-return annotation, linker-neighbor assumption, probe, or production change. No gate status changes. The old root v17 wording is retained only as pinned historical research.
