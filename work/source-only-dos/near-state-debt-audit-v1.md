# Source-only near-state debt review

This review uses current canonical modules from `layout/manifest.json`, the 29 root-confirmed effective sources selected by `work/source-only-dos/static-completeness/index-v1.json`, the accepted CRT startup-clear receipt, and OMF metadata/code from the two hash-pinned MSC runtime libraries. It does **not** read or emit any original-executable or accepted data-debt bytes. `near-state-debt-audit.py` verifies canonical/strict-source pins and records all named references, then runs `near-state-debt-runtime-scan.py` to verify runtime archive/member pins and scan OMF names, fixups, and selected code. Generated outputs remain under `build/workers/dos_near_state_debt_review/`.

Pins in `source-scan.json`: `layout/manifest.json` `025a0a9255d910cae4b122ab5a3f3fb40888bb456d7fe42158db7c9e622fcf50`, `layout/symbols.json` `0f5dd5b0a211945a97782cfccdb9bb31b0dfd07fcde5df4d4f9486b487eb0125`, behavior registry and strict index, plus startup receipt `44b4f2afca0988722d1ff10df933771569c61cc02cd8f11b20ff4ffe8a8af97e`. Both audit scripts are pinned in the source receipt; the runtime receipt also pins `ndisasm.exe` SHA-256 `5789e415cc0a62b2211dd11c2bbd87225ce300ac45afb8e899f6dc8557bdcbbb`. All manifest module source hashes and all 29 strict effective source/receipt hashes verified. The scan found target-name references in 27 canonical modules and 13 strict effective sources; there were no canonical or strict-effective numeric ASM literals for `8CCA/8CCB` (or the Rect addresses scanned). Runtime library pins are `llibcr.lib` `3d0c6ae92972789e87def01fa96351c39216d731d5c880370155c5613d78c884` and `libh.lib` `a4492e8f63da409d949643fd448f29e65e2cc9a8f2deea977372177bbe0ad818`.

## Findings

- **`g_5A97`: a one-byte mode selector; its source meaning is initialized before the source-visible startup reads.** Canonical users declare `char near` (18 declarations) and `unsigned char near` (3 declarations); there is no canonical storage definition or address-taking. The signed path treats `-1` as “detect mode” (`src/root/m205F.c:132-137`). `IBMInitStuff` calls `ReadConfig` before reading the selector (`src/S20/m39F1.c:68-69,141`); each recognized configuration case assigns it, while invalid/missing configuration exits (`:216-253`). The `/d` cases also assign it before the selector switch (`:82-114`). Mode detection replaces `-1` or exits before later mode-table indexing (`src/root/m205F.c:132-153`). `main` calls `IBMInitStuff` before its later selector read (`src/root/m15F8.c:90-96`); the preceding drive-reset helper has no selector access (`src/S15/m384C.c:66-82`). This establishes the normal source startup write-before-read path; it does not establish a pre-main value or erase the cross-TU signedness disagreement. The accepted CRT clear interval excludes this address, but that does not affect the proven source writes-before-reads.

- **`g_8CCB`: a single-byte fallback-message selector read.** The canonical and strict-effective occurrence is the declaration and indexed read in `src/root/m1C62.c:329,331-354`; `g_567A` has 14 entries and `f_1C62_06A6` uses the selector without a range check only when `err > sys_nerr || err < 0` (`:350-354`). No scanned source assigns it, takes its address, or performs arithmetic on it. Separately, the startup receipt proves its registered byte at `55B3:8CCB` is zero-filled in DGROUP interval `[0x8b9e,0x94f0)` before `main`. That is a proven initial-state fact; it does not establish an owner or rule out a later writer.

  The application installs `_harderr(f_208F_058B)` at `src/S20/m39F1.c:153-154`; that handler returns `3` (`src/root/m208F.c:300-303`, the DOS header’s `_HARDERR_FAIL`). In the pinned OMF, selected `dos\\harderr.asm` is an 87-byte code / 6-byte `_DATA` member, has `__harderr`, `__hardresume`, `__hardretn_return`, and `__oldsp` publics, and no matching 8CCA/B name or communal. Across both pinned archives, all 423 OMF modules parsed with no errors and no public/external/COMMDEF name matching the target; the 98 accepted selected members’ 91 code segments and fixups contain no direct numeric 8CCA/B reference. `dos\\doserr.c` is present in the archive but is not selected into the accepted runtime; it exposes `_dosexterr` and calls `_intdos`, with no target owner. These checks reduce the selected-runtime ownership lead but do not prove that DOS or an unselected external component cannot affect the byte.

- **`g_5A9C` is a four-word Rect view; `fd_55B3_5AA0` and `fd_55B3_5AA2` are its interior right/bottom words.** The address registry places `g_5A9C` at `55B3:5A9C` and the two aliases at `+4` and `+6`. Canonical Rect declarations have signed `int left, top, right, bottom` (`src/root/m1E57.c:5-10`, also `src/root/m205F.c:3-8` and `src/S17/m384C.c:4-9`). `src/S10/m35F5.c:155,229-238` declares a two-`int` view at `+4` and indexes elements 0/1 as right/bottom. No independent canonical owner exists for the aliases.

  The source-derived lifecycle is: canonical root defaults set screen width/height to 640/350 (`src/root/m1B4E.asm:26-27`); the selected video-driver sources replace them for their modes (for example S00 `src/S00/m31AD.asm:3588-3591`, S01 `src/S01/m3126.asm:155-158`, S02 `src/S02/m3126.asm:124-127`, S03 `src/S03/m3126.asm:155-160`). `f_205F_0004` selects and initializes a driver, invokes the font callback, then stores the resulting dimensions into `g_5A9C.right/bottom` (`src/root/m205F.c:156-211`). `IBMInitStuff` calls it before `o17_384C_0000` (`src/S20/m39F1.c:146,153`); that routine passes the Rect to `f_1FD2_03EB`, which reads/copies all four fields (`src/S17/m384C.c:19-27`, `src/root/m1FD2.c:230-238`). Thus the startup path explicitly sets the interior right/bottom before this direct Rect copy. This does not prove there is no earlier indirect read through a live `g_5AAC` pointer.

  Clipping uses half-open bounds: a point is outside at `x >= right` / `y >= bottom`, and the inclusive last point is computed using `right - 1` / `bottom - 1` (`src/root/m1D8E.c:25-38,48-51`). Startup drawing passes `(0,0,width,height)` (`src/S20/m39F1.c:162`). Together these make left/top zero a plausible whole-screen semantic candidate, but no canonical source writes those two fields. When the default clip list points at `&g_5A9C` (`src/root/m1E57.c:165,184,381-384`), traversal increments by one 8-byte `Rect` and checks each record’s `top` for `0x8000` (`src/root/m1E57.c:173-175`; similarly `src/root/m1D8E.c:176-180`). Therefore the source view requires a following sentinel Rect at `g_5A9C + 8` (address `55B3:5AA4`), with its `top` word at `+10` (5AA6) equal to `0x8000`; source does not initialize that adjacent record. The CRT clear interval excludes the Rect. Because left/top and the sentinel lack a source initializer, and an earlier indirect clip-list read through `g_5AAC` is not ruled out by this source audit, there is not enough independent source proof to package an initialized Rect storage candidate. No historical owner/order is inferred.

## Four unresolved facts

1. `g_5A97` has no source storage owner, and canonical consumers disagree between signed and unsigned byte declarations. Its pre-main value is not recovered, though normal startup writes it before mode use.
2. `g_8CCB`'s initial zero is established by CRT startup; its source/runtime storage owner and any post-startup writer/lifecycle remain unknown.
3. `g_5A9C.left/top` have no source assignment. Zero follows from the 0-origin whole-screen path only as an inference, not as a proven initializer.
4. The following Rect at `g_5A9C + 8` must carry the `top == 0x8000` terminator for the default list, but source does not initialize it; the initial `g_5AAC` pointer and possible pre-dimension indirect reads remain unresolved.

## Limits and reproduction

This is a read-only audit of current canonical/registered sources, the accepted startup receipt, and pinned runtime libraries. It does not inspect the original executable, use accepted initial-data bytes to infer initializer values, run a compiler/emulator, identify historical object ownership, or establish the full pre-startup `g_5AAC` pointer lifecycle. No storage admission or provider proposal is made. The generated-source conclusion is limited to a write-before-read path for `g_5A97`, a CRT-zero startup value and unresolved later lifecycle for `g_8CCB`, and a typed Rect/interior alias plus dimension-write/sentinel requirements for `g_5A9C`.

Reproduce both scans from pinned repository inputs with `python work/source-only-dos/near-state-debt-audit.py`. It writes `source-scan.json` and `runtime-omf-scan.json` under `build/workers/dos_near_state_debt_review/`; it reads no initial-data vector or original executable.
