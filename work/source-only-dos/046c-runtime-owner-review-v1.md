Scope: static/original-image research for the exact 046C:0000 read, plus controls from installed RTLink versions. No canonical source, manifest, oracle, linker input, or Git file changed. The request labels root:171C; repository evidence locates the only matching literal/read at root:0093:00B8 (GetRRandSeed). root:171C is the allocator module and has no function row at offset 046C and no 046C0000 source literal.

## Original image: exact operation and load model

Pinned original assets/SIMANT.EXE SHA-256 is aa0596c6766322a8229ee3c36e57048c92adc82d50fbe2ef37afb8b85fcf4f11. At root:0093:00BF, bytes BB 6C 04 load immediate BX=046C; ES=BX, BX=0, then ES:[0] and ES:[2] are read. This is the far dword read 046C:0000, physical 0x46C0. The only nearby MZ relocation is at root:0093:00BD (the preceding __aFchkstk far call); there is no relocation on the immediate 046C. The value is therefore absolute, not an MZ load-relative symbol/fixup.

The MZ header has CS:IP=2CFF:06F8, SS:SP=5F02:1000, and 3,683 MZ relocations. SS:SP has top 6002:0000 and lies in the documented DGROUP/BSS/stack load-relative range 55B3–6002. RTLink's ih_tmp_stack field is also 6002. Those identify the executable's initial and overlay-manager initialization stack coordinates; neither identifies segment 046C. Runtime load/PSP base is not in the static MZ header, so a load-relative root or overlay address cannot be equated to absolute physical 046C:0000.

The original RTLink header is at 2CFF:0B5F, bytes 01 00 02 60 00 00 00 00 00 00 00 00 1C 00 00 00 00 18: ih_flags=1 (far reload), temporary-stack segment 6002, 28 sections, zero data-save sections, and reload-stack size 0x1800. The 18-byte section table starts at 2CFF:0B71; its 28 records end at 2CFF:0D69. Under the documented RTLink RELOAD layout, this yields a manager-owned reload-stack start at the table end and a derived candidate interval 2CFF:D69–2569 (0x1800 bytes). This is a load-relative coordinate in the manager/$$OVLINFO area, not absolute 046C. Because the exact SimAnt RTLink manager source/version is still unavailable, treat the computed start as metadata-derived, not a source-level public symbol or independently recovered manager implementation. The vector table starts at 2CFF:25F6, after that candidate interval.

## Linker controls and scope

The toolchain profiles pin RTLink/Plus 4.00 (RTLINK.EXE SHA-256 dff0a988…e87c74) and 6.10 (RTL-SWAP.EXE SHA-256 daae0a8c…1cfe3). Neither is claimed as SimAnt's exact linker. The 4.00 source OVLMGR.ASM (SHA-256 2e67a439…3a741) documents the manager info layout: section descriptors, data-save descriptors, RELOAD stack, cache metadata/names, and vectors; it computes the stack offset from the table pointers and ih_rstk_size. 6.10 source similarly names manager-owned stack_seg/stack_offset and initializes stack_seg from seg $$OVLMGR. This corroborates that RELOAD stack storage is manager/link metadata, while remaining version-specific evidence. RTLink 4.00 stock records are 16 bytes and its intercept differs from SimAnt's 18-byte records/manager, so its absolute layout cannot be substituted for the original.

The existing test-owned symbolic-alias probe build/workers/dos_linker_aliases_v2/report.json is a relevant positive/negative control: for both pinned linkers, a correct named near/far owner plus offset prints PASS; wrong near/far offsets and malformed unsuffixed offsets print FAIL. Its contract is limited to aliases of test-owned _DATA/FAR_DATA objects. It proves linker alias binding and contrast behavior, not a historical owner at 046C and not placement of the SimAnt manager stack.

## Owner disposition

No original-image or installed-linker evidence assigns absolute segment 046C to the MZ initial stack, RTLink reload stack, an overlay section, or a named DOS/BIOS object. The registered function is marked unreached; static audits found no direct call, overlay vector, or data relocation to it. The byte-level operation remains an exact absolute RAM read if exercised, with intended owner unresolved. The existing BIOS tick annotation is wrong for these operands: the BDA tick address is 0040:006C (linear 0x046C), whereas the image reads 046C:0000 (linear 0x46C0). Do not retarget it to the BDA or invent a symbolic owner. If code ever targets the known RTLink reload stack, bind to verified manager storage/placement; that does not make this read a reload-stack reference.
