# Enhanced menu evidence

The [implementation and wait inventory](../../docs/enhanced-mode/menus.md)
separate source facts, bitmap transcriptions and native presentation choices.

Reproduce menu bitmap provenance and the source-loop census with local verified
assets; the output contains game-derived PNGs and must remain ignored:

```powershell
python evidence/enhanced-mode/menu_resources.py --out build/workers/enhanced-menus/resource-proof
```

`resources.json` records decompressed kind-2 payload hashes and transcription
positions for 4500 (ant), 4502 (queen), 4504 (spider), 6000 (scent),
5000–5006 (experiment menus), and 5010/5011 (Quick/Full Tools). DOS menu window
resources 6–17 and 32 have bitmap object 1 and textless type-1 hit objects.
Magnify 29 uses bitmap 4510; its dynamic values are observed after the original
font output, not recomputed by the native presenter. The Win16 database inventory
in `build/workers/enhanced-design/resource-inventory.json` corroborates this
bitmap/hit-object arrangement; it is not a runtime dependency.

Native/source choice evidence is generated by `portable/tests/enhanced/menus.py`
and included by the full `action_equivalence.py` registration. It retains every
raw named-view difference. Menu choices use actual Win32 key/mouse messages;
source controls use the original source object-event path. The probes assert
native enabled/check states through the live popup HMENU, visible world clients,
retained player/spider scene, monitor placement and recovery of the outer loop.
Shift and Alt tests alter only host input state and ordinary SDL keyboard input,
never game memory. Full Game and spider setup use normal scenario/exchange input.

Final artifacts, exact commands, hashes, desktop audits and original failed
preflight attempts live under `build/workers/enhanced-menus/`. The first expanded
desktop ancestry audit rejected a compiler build because an older system
process's parent PID had been reused. PID creation-time ordering corrects that
false ancestry; no game had launched in that attempt. The simulation fixture's
own `EditMessage` observer now chains at the production wrapper's real boundary;
the small retained `wrap-probe` demonstrates the GNU linker rule. No production
object or canonical target is removed from that fixture link.

The intermediate `final-build` run passed all 101 existing action cases but
failed the three command-menu Help cases: the source help client displayed and
returned, then left native focus empty. The retained focus diagnostic records
that failure. The correction preserves originating focus on entry to each
source modal client, in addition to the native proximity transaction. All three
focused Help checks passed before freezing `release-build` for the final full
round. Intermediate stale-pin refusals remain separate from that final receipt.
